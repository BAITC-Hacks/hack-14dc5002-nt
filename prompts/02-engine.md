Модель:
- Ровно пять уникальных мероприятий, бюджет не больше 100. Все числовые свойства читаются из каталога, не из запроса.
- Проверяй версию модели, неизвестные/дублированные ID, доступность события, requires/excludes, бюджет. Не требуй по одному мероприятию на направление.
- На невалидном плане valid=false, officialScore=null, metrics=null, trace=[]. При подсчете draft-бюджета используй уникальные известные ID, но дубликаты/неизвестные ID остаются ошибками.
- Горизонт 12 месяцев берется из config. При horizon >= lag полный заданный эффект активен, иначе ноль. Лаг — ступенчатое демо-допущение.
- Для каждой пары район/показатель сложи baseline и активные эффекты, затем один раз clamp к 0..100. Все показатели направлены «больше — лучше».
- Взвесь показатели внутри районов и районы в городе. Веса берутся из config/catalog, не захардкожены в коде. В API не округляй, trace содержит сырые примененные эффекты до clamp.
- Детерминированность: одна версия каталога + один набор ID + один контекст события → одинаковый результат. Сортируй копию ID, не мутируй входные данные. Без Math.random, сети, дат и LLM.
- Проверь каталог: уникальность ID, существование ссылок, конечные числа, неотрицательные цена/лаг/веса, сумма весов 1. Не выдавай поврежденный каталог за валидный.
