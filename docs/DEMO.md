# Сценарий демонстрации и приемка

## Проверенный каркас — 23 сентября 2026

Ветка `Bakytzhan`: Next.js запускается, каталог доступен по HTTP, клиентский адаптер
поддерживает подготовленные mock-сценарии `demo-v1`. Это проверка каркаса, а не
готового симулятора. Интерфейс Сембы и движок Никиты в эту ветку ещё не включены.

### Запуск

```sh
npm ci
npm run dev
```

В локальном `.env.local` для первого запуска нужны только публичный переключатель
mock и выключенный AI:

```dotenv
NEXT_PUBLIC_USE_MOCK_API=true
AI_ENABLED=false
```

Если `.env.local` уже существует, сохрани остальные настройки. API-ключ для каркаса
не нужен; этот файл игнорируется Git и не передаётся другим участникам.

Для production-запуска:

```sh
npm run build
npm run start
```

### Исправления по результатам проверки

- Playwright теперь ищет только `tests/e2e`, а Vitest исключает эту папку.
  Раньше `test:e2e` подхватывал Vitest-тесты и падал.
- Mock-адаптер возвращает независимые копии fixtures. Изменение полученного ответа
  не портит следующий вызов; это покрыто регрессионными тестами.
- Дополнены проверки всех пяти функций адаптера, запросов fetch, ошибок и строгих схем.

### Что ещё не работает в реальном приложении

При HTTP-проверке `POST /api/simulate`, `/api/events/preview`, `/api/events/confirm`
и `/api/explain` вернули **404**: этих маршрутов ещё нет. Серверные Zod-схемы и
JSON-parser уже есть, но будут подключены к POST-маршрутам на этапе интеграции.

Страница пока содержит только заголовок и описание. Выбора мероприятий, результатов,
событий и сохранения снимков в этой ветке нет. OpenAI, шаблонные серверные объяснения
и переключатель RU/KK/EN ещё не реализованы; live-запросов генерации при этих проверках
не выполнялось. Ранее отдельно проверялась доступность ключа и выбранной модели.

Для передачи Сембе переносить каркас с сохранением его `page.tsx`, `globals.css`
и `src/features/`. До подключения Никиты согласовать переход от `demo-v1/actionIds`
к его контракту `organizer-v1/selections` и форму запросов событий. Ключи не передавать.

## Запланированный сценарий demo-v1

Ниже описан сценарий будущей интеграции по исходному контракту `demo-v1`, а не
подтверждение готовности UI/API. После согласования контракта Никиты сценарий и
ожидаемые числа потребуется обновить совместно с командой.

## Основной проход
Открыть «Аким на 5 часов». Видны 100 условных единиц, правило пяти решений, синтетические данные и горизонт 12 месяцев. Нажать «Загрузить демо-план» либо выбрать bus_lanes, school_new, park_local, lighting_smart, services_online. Проверить пять действий, расход 90 и рассчитанный результат 57.0 (UI может использовать десятичную запятую).

Зафиксировать исходный результат. Открыть событие «Строительство школы отменено: участок недоступен». В ветке четыре мероприятия, расход 60, доступно 40, официального результата ветки нет. Исходный снимок 57.0 / 90 остается на экране.

Из предложенных вариантов выбрать именно «Модульные учебные корпуса» (school_modular), а не автоматически первый вариант. Они стоят 36, то есть дороже отмененной школы за 30, но укладываются в 40 свободных единиц. Предварительный результат относится к пятерке после замены, не к четверке черновика.

Подтвердить. Получить пять мероприятий, расход 96, новый Score 56.6, изменение -0.4. Показать изменения по районам и объяснение компромисса. Не изображать падение как искусственное «улучшение»: задача — показать последствия и возможность адаптации, а не гарантировать рост Score.

В этом каталоге автобусный парк дает практически тот же городской Score, но другой районный/отраслевой результат; при равном Score он ранжируется выше из-за меньшей стоимости. Поэтому выбираем конкретную замену по названию, а не «первую карточку». Это позволяет обсудить разницу между общим баллом и социальными приоритетами.

## Текст для защиты
«У вас одинаковый бюджет и ровно пять решений. Результат рассчитывает открытая формула; AI объясняет последствия, а не придумывает баллы. После сохранения исходного плана участок под школу стал недоступен. Мы не удалили исходный результат и не оценили некорректный план из четырех решений: предлагаем проверенные замены, учитываем оставшийся бюджет и сравниваем две валидные пятерки».

## Приемка перед показом
Проверьте реальный путь с mock=false; сборку без API-ключа; пять действий в бюджете; 4/6 без Score; превышение 100 без Score; недоступную отмененную школу; зависимость safety_sensors от lighting_smart; отсутствие мутации исходного результата; обработку пустых замен; перезагрузку снимка; timeout AI с пометкой шаблонного ответа. Числа должны совпадать с golden fixtures неизмененной demo-v1.

Публичная копия не должна иметь незащищенный платный AI endpoint. При отсутствии доступа к хостингу/защиты показывайте локальный запуск либо отключите AI в публичной копии. Подготовьте локальную резервную копию и честно подписанный template-режим. Не выдавайте отсутствие живого AI за полноценную интеграцию.

Интегратор дополняет этот файл реально проверенными командами запуска, env-настройками без ключей, результатами e2e и фактическим адресом развертывания при его наличии. Перед защитой сверить требования с полным заданием организатора, которого в этом пакете нет.
