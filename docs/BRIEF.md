# Проект и рамки MVP

## Что известно из доступного контекста команды
- Трек: «Аким на 5 часов», владелец задачи — Astana Innovations.
- Виртуальный городской бюджет распределяется через решения по транспорту, озеленению, социальной сфере, безопасности и сервисам.
- Пользователь принимает ровно пять решений и видит Astana Quality of Life Score с объяснением.
- В текущем уточнении команды бюджет ограничен 100 условными единицами.
- Киллер-фича: после сохраненного исходного результата одно мероприятие отменяется или открывается новая возможность. Пользователь подтверждает замену, видит старый/новый Score и изменения по районам.
- Команда: три человека, каждый работает через Codex. В предыдущем контексте обозначены четыре часа и доступные API-бюджеты OpenAI и NVIDIA примерно по $50. Эти суммы не являются оценкой будущих расходов.

## Чего здесь нет
Нет полного официального задания, таблиц организаторов, утвержденной формулы, полного списка районов и критериев жюри. Все ниже — инженерные предложения команды для MVP, а не требования Astana Innovations.

## Явные допущения v1
Три условных демо-района D1/D2/D3 с равными весами; пять нормализованных показателей с равными весами; горизонт 12 месяцев; лаг ступенчатый; эффекты аддитивны с ограничением 0..100; отрицательные эффекты допустимы. Стоимость выражена в условных единицах, не в тенге. Полный возврат отмененного мероприятия означает пересмотр еще не исполненного плана. Одна замена и одно событие на ветку. Для повтора создается новая ветка от исходного результата.

Не требуется выбирать ровно по одному мероприятию каждого направления, пока организатор явно не потребует этого. Не нужно тратить все 100 единиц. Не называем формулу официальной: officialScore — имя поля утвержденного результата в приложении, а не признание модели городом.

## Главный пользовательский путь
План из пяти → серверная проверка → результат и объяснение → отдельная ветка события → предварительные варианты замены → подтверждение одной замены → сравнение со снимком исходного результата.

В случае отмены промежуточный план из четырех не имеет Score. Предлагаемые замены имеют собственные предварительные расчеты для полных пятерок. При новой возможности старая пятерка формально допустима, но событие не подтверждено: пользователь выбирает, какое мероприятие заменить новым.

## Приоритеты
Обязательно: рабочий сквозной путь, валидатор, объяснимая формула, ограничения/лаг, районные результаты, одно событие отмены, AI или честный fallback, отсутствие утечки ключей, воспроизводимое демо.
Следом: второе событие-«возможность», до трех кандидатов, хорошая верстка, экспорт снимка JSON.
Не делать до приемки: чатбот, настоящую интерактивную GIS-карту, аккаунты, leaderboard, БД, сложную анимацию, внешние данные в реальном времени, multi-agent runtime, второй AI-провайдер.

## Распределение
Участник 1 — интерфейс, состояние клиента и экран сравнения.
Участник 2 — данные, формула, валидация, события и детерминированный поиск замен.
Участник 3 — bootstrap, контракт, API, AI, интеграция, запуск и демо.
У каждого своя ветка: feat/ui, feat/engine, feat/api-ai. Общий исходный commit: shared-contract-v1. Одновременно редактировать одну рабочую папку нельзя. Отдельные компьютеры используют отдельные клоны; несколько агентов на одном компьютере — отдельные worktrees с разными ветками.

## Контрольные точки внутри четырехчасового бюджета команды
00:00–00:15: участник 3 поднимает каркас, зависимости, общий контракт и mock API; участники 1/2 читают свои задачи и сверяют данные.
00:15–01:15: интерфейс на mock; движок и тесты; API-оболочки/AI fallback.
01:15–02:00: первая интеграция: реальный каталог → пять действий → реальный результат без LLM.
02:00–03:00: отмена → замены → подтверждение → сравнение; подключение AI без влияния на расчеты.
03:00–03:30: интеграционные проверки, запуск на целевой среде, второй тип события только при зеленом первом пути.
03:30–04:00: заморозка возможностей, исправления, репетиция и резервный локальный запуск.
