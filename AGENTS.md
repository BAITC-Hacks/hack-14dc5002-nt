# «Аким на 5 часов» — обязательный контекст для Codex

## Продукт
Веб-симулятор: пользователь выбирает ровно пять уникальных мероприятий, укладывается в 100 условных единиц и видит Astana Quality of Life Score, показатели и результаты по районам. Затем в отдельной ветке происходит событие, пользователь подтверждает одну замену, интерфейс сравнивает два валидных плана. Это учебная модель, а не прогноз реального города.

## Источники требований
Читай docs/BRIEF.md, docs/CONTRACT.md и свой файл в prompts/. Полного официального задания в этом пакете нет. Требования организатора, когда их предоставят, имеют приоритет над нашими явно помеченными допущениями. Не придумывай требования организатора. Изменение требований фиксируй отдельно, не переписывай архитектуру молча.

## Инварианты
- Итоговый план: ровно 5 уникальных actionIds; сумма стоимости <= 100.
- Не требуется по одному мероприятию на каждое направление: такого правила пока не предоставлено.
- При 4/6 мероприятиях, неизвестных/дублированных ID, недопустимой стоимости, нарушении ограничений: valid=false, officialScore=null, metrics=null. Не показывай ноль вместо отсутствующего результата.
- Стоимость, эффекты, лаг, ограничения, доступность берутся только из серверного каталога. Клиент отправляет ID и modelVersion, не «готовый» Score.
- Все показатели нормализованы: больше означает лучше. Для congestion/emissions/responseTime нельзя напрямую использовать положительное направление.
- Симуляция и поиск замен — детерминированные чистые функции. LLM не вычисляет Score и не изобретает варианты.
- Исходный снимок не мутирует. Событие работает только в отдельной ветке.
- При отмене выбранного мероприятия в демо возвращается вся его стоимость: это предположение до начала исполнения, не правило о реальных расходах.
- Доступно на замену = 100 - стоимость четырех оставшихся мероприятий, включая прежний остаток.
- Новое мероприятие из события заранее полностью описано в каталоге и недоступно до этого события. Оно заменяет одно старое, не добавляется шестым.
- Предварительный результат кандидата считается только для полного валидного набора из пяти и маркируется как предварительный. Он не заменяет сохраненный результат до подтверждения.
- Один горизонт и одна версия модели для сравнения. При смене версии старые снимки не пересчитывать незаметно.
- Синтетические данные и условные районы D1–D3 видимо помечаются. Не называй их реальной статистикой или административным делением Астаны.

## Архитектура
Одно приложение Next.js App Router + TypeScript + Tailwind. Проверка JSON — Zod. Серверные route handlers импортируют движок. OpenAI SDK только на сервере. Для MVP не нужны БД, авторизация, GIS, Python-сервис, RAG, LangChain, мультиагентный runtime, Docker или второй AI-провайдер. Снимки хранятся в localStorage как удобство, не как доверенный источник чисел.

## Работа
Вначале изучи текущий репозиторий и git status. Не создавай новое приложение поверх существующего. Выполни задачу кодом, а не только планом. Делай небольшие коммиты по готовым частям. Если нужен чужой файл, опиши точный патч владельцу. Не объявляй задачу завершенной по одному скриншоту.
Проверяй typecheck, тесты и build в доступном окружении. Не утверждай, что запускал проверку, если не запускал; отличай ошибки окружения от ошибок кода. Не удаляй тесты ради зеленого результата. Не добавляй зависимости без согласования с интегратором.

## Безопасность и AI
Ключи только в .env.local / серверных секретах, никогда не в NEXT_PUBLIC_, Git, клиенте или логах. LLM вызывается после завершенного базового расчета и после подтверждения события, но не при каждом клике. Используй timeout, ограниченный ответ, проверку схемы/ID и честный шаблонный fallback source=template. Отсутствие ключа не ломает сборку или симуляцию. Structured Outputs не заменяет проверку фактов. Основные числовые карточки всегда получают значения из движка, а не из текста AI.
